# Code map: languages (AIG-124, AIG-487)

For translators: `docs/i18n.md` (rules, the checker, adding a language, per-language notes).

- Every screen text lives in `public/lang/<code>.json`, one flat object of readable, area-grouped keys (`card.accept`, `inbox.empty.title`). `en.json` is complete and the fallback; other files may be partial (English shows per key) but may not hold a key English lacks or change a `{placeholder}`: `node tools/i18n/check.mjs` checks, and QA `i18n` runs it over every shipped file. A value is a string or a plural object `{ one, few, other, ... }` with `{count}`.
- `public/lang/languages.json` lists the 121 languages (code, label, own name, Intl `locale`, `dir: "rtl"`, `region`/`notRegion`/`base`, `fun`). `GET /api/langs` (lib/routes/meta.js) lists the files that are in and parse; only those count (`LANGS`), so translations arrive one by one.
- `t('key', { name })` (js/i18n.js, loaded right after core.js) returns the text in the chosen language, else English, else the key. A plural object picks its form with `Intl.PluralRules(i18n.locale)` for `vars.count`. `{name}` placeholders are filled from vars; vars are NOT escaped, so wrap user data in `esc()` and the result in `esc()` when it goes into HTML. Keys ending `.html` hold markup and are inserted raw.
- The language is `localStorage` `aigile.lang`, else the device language (`deviceLang()`: region, LocoRadio's fallbacks, never a fun one), else `en`. `loadLang()` fetches the list and files and sets `<html lang>`, `<html dir>`, `i18n.locale` (pass it to `toLocale*String`); `app.js` renders only after it (`i18n.ready`); polls and timers wait for it. The 🌐 picker (`langPickHtml()`: Setup, the setup wizard) calls `setLang`, which reloads; the top bar only has the quick English switch `#enBtn`. Static text in `index.html` uses `data-i18n`, `data-i18n-title`, `data-i18n-label`.
- Right to left: the CSS uses logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`); write new CSS that way. Physical left/right stay only for the desktop window buttons and 50% centring. QA `rtl` checks the pages with a stubbed Arabic file.
- Add a string: put the key in `en.json` (and the same key in `nl.json` and `nl-BE.json`; other languages fall back until their translator catches up), call `t()` where the text is. Do not build a sentence from pieces; give the translator one string with placeholders. Do not name a local variable `t` in a function that calls `t()`. Lists that held text at load time are getters or functions now (`COLS`, `THEMES`, `lanesList()`), so they follow the language.
- Dev words: wrap a developer word in the English file as `{{dev:commit}}` (also `{{dev:Backlog}}`, `{{dev:test}}`, `{{dev:sprint}}`, `{{dev:bug}}`). For now `t()` renders the marker as the word itself; a later card will show the English word in brackets for Dutch and Flemish and add tooltips, finding the markers with `/\{\{dev:([^}]+)\}\}/`.
- Dutch word choices (card = kaart, board = bord, ...): `docs/lang/nl-glossary.md`; follow it when adding Dutch strings.
- Flemish (`nl-BE.json`) word choices are in `docs/lang/nl-BE-glossary.md`.
- Not translated: server and CLI text (`lib/`, `aigile.js`, API error messages), the Setup field labels and help (they come from the server), data users and teams typed, card ids, project names.
