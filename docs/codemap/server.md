## API routes
All in `lib/routes/*.js` (patterns are the regexes there). The list with payloads is in the README's API table. Unknown `/api/*` paths return 404 JSON from `server.js`. A handler may return a promise (the DM routes talk to the relay).
- DMs: `GET /api/dms` (on, relay, mailbox, contacts, lastPoll), `POST /api/dms/settings` `{on?, relay?}`, `POST /api/dms/poll`, `POST /api/dms/invites` `{name?}`, `POST /api/dms/accept` `{code, name}`, `GET /api/dms/contacts`, `PATCH`/`DELETE /api/dms/contacts/:id` (`{name?, checked?, blocked?}`), `GET`/`POST /api/dms/contacts/:id/messages` (`{text, attachments?: [{name, type, data}]}`), `GET /api/dms/contacts/:id/files/:fid`, `GET /api/dms/contacts/:id/messages/:mid/raw` (what the relay sees).
- Sharing (AIG-304): `GET /api/shares[?slug=]`, `POST /api/shares` `{slug, contact, allow?}` (offer), `PATCH /api/shares/:id` `{on}` (the 🔗 switch), `POST /api/shares/:id/accept` `{slug, allow?}`, `/decline`, `/ping`, `/unlink` `{forget?}`. Cards (AIG-305): `GET /api/shares/:id/preview?card=`, `POST /api/shares/:id/cards` `{card, force?}`, `DELETE /api/shares/:id/cards/:card`, `POST /api/shares/:id/held` `{card, at}`, `GET /api/shares/:id/inbound`, `POST /api/shares/:id/inbound/:share/comments` `{text, force?}`, `POST /api/shares/:id/inbound/:share/take`. AIG-306: `PATCH /api/shares/:id` `{teamRead}`, `POST /api/shares/:id/test` `{card, text, force?}`, `POST /api/shares/:id/inbound/:share/verdict` `{verdict: accept|back, note?, force?}`, `GET /api/shares/:id/files/:fid` (a download), `GET /api/projects/:slug/cards/:id/friend` (what a team is given).
- Invite links (AIG-347): `GET /api/join` (`{url, ownerKey, codes, error}`), `POST /api/join/codes` `{help: 1|2|3, name?}` (409 while DMs are off), `POST /api/join/settings` `{url}` (default `https://aigile.lol`; `AIGILE_JOIN` overrides). `helpLevel` ('', 1, 2, 3) is a pref in `GET`/`POST /api/setup`.
- Ask a mate (AIG-210): `POST /api/dms/contacts/:id/ask` `{text}` (up to 1000 characters; a question for their AI), `GET /api/dms/asks` (`{asks, running, flags}`: friends' questions waiting for me), `POST /api/dms/asks/:contact/:msg/yes` (✅: starts the one capped run; 409 while one runs), `/no` (✋: a polite not now).

## Local-only settings
`aigile.local.json` (git-ignored; values are machine-specific):
- `usageDir`: folder of the agents' session logs (`AIGILE_USAGE_DIR` overrides).
- `globalSettingsFile`: the agent's global settings file, used to show how to switch the status line on.
- `agent.command`: program background runs start (one `*` path segment allowed; `AIGILE_AGENT_COMMAND` overrides).
- `agent.notesFile`, `agent.settingsFile`: file names `onboard` writes in a project folder.
- `avatarsDir`: the agents' picture library folder (AIG-150; empty: `data/avatars`).
- `dmRelay`: default DM relay address (`AIGILE_RELAY` overrides; `POST /api/dms/settings` can set one too).
- `WAYS-OF-WORKING.md` (repo root) is the owner's private rules for every team, git-ignored; a new install gets `docs/starter/WAYS-OF-WORKING.md` with the name filled in (`ensureWays` in lib/setup.js).
- `owner`: the board's human, whose comments wake teams and who gets questions and tests (default "Owner"; `AIGILE_OWNER` overrides). Code calls this person `isRich()` / `me()`.
- `lead`, `night` (AIG-235): what kind of lead, set by the Setup questionnaire or its switches (`prefs` in `GET`/`POST /api/setup`, `prefsOf`/`setPrefs` in lib/setup.js): `lead.tidyCards` (AIG-234), `lead.chatty` (default for new projects; `chattyAll` also sets every active project), `lead.go` (`ask`/`small`: one rule line in `aigile brief`), `night.watchAll` (false: going quiet ticks no project for the watchman; an empty `watch` list means none). Dev words explained stays per browser (`aigile.explain`).
- `runs` (AIG-153): `where` (background, terminal, vscode, other) and `cmd` (the Other command, `{folder}` filled in): where every team runs unless its project picks its own in 🎨 Look (`p.runIn`, `p.runCmd`). Saved through `prefs.runIn` / `prefs.runCmd` in `POST /api/setup`.
