# Code map: data

- `data/<slug>.json`: one file per project (cards, comments, team, log, `teamSeenAt`); written atomically via a `.tmp` file. Git-ignored.
- `data/backups/` (AIG-1258): `YYYY-MM-DD/` once a day (boards, `project-order.conf`, `_settings.json` without token/secret/password/key fields, `backup.json` with card counts), and `<day>T<time>-replaced/` made by a restore (a damaged file kept as `.bad`); 7 of each kept. `data/damaged/<name>-<time>.bad` (AIG-1261): a copy of a board or settings file that did not parse, made on first read.
- Spaces (AIG-433): a project's `parent` is the slug of the project it sits in (none = top level, any depth, no loops: `checkParent` in store.js). `GET /api/projects/:slug` adds `space: { up, kids }` (the spaces it sits in, outermost first, and its own projects).
- Board templates (AIG-170): the New project dialog (`boardTemplateNames` in js/dialogs/) just PATCHes `columns` with names after create: Kanban = none, Scrum = names for the first four statuses, Your own = comma list in status order.
- A project's `columns` (AIG-116/118): per status `{ status, name?, emoji?, color?, hidden?, wip? }` in board order; `wip` is the card limit (0/empty = none), checked 0..999 in the PATCH route, drawn by `renderBoard`.
- A stand-up card (AIG-133) has `standup: { at, reports: [{ name, done, next, blockers, at }] }`; the CLI `standup` command fills `reports`.
- `data/limits.log`: one JSON line per plan usage change (or every 5 minutes).
- `data/logs/<slug>.log`: what the team's background runs printed.
- `data/logs/_ask.log`: ask-a-mate runs (AIG-210): start, tokens, exit (never the question text). Their cost rows go in `data/logs/_runs.jsonl` with `slug: '_ask'`.
- Ask a mate questions and answers live in the friend's chat file `data/dms/<contact>.json` as lines with `kind: 'ask' | 'answer'`, `q` (the question id) and, for a question, `state` (`waiting` / `running` / `answered` / `declined`, plus `failed` when a run didn't work).
- Presence ("heard from") and the running processes are in memory only.
- Chats at rest (AIG-1166, `lib/atrest.js`): friends' DM chats `data/dms/<contact>.json` and group chats `data/groups/<id>.chat` are sealed on disk with AES-256-GCM (`aigile-atrest-v1:` + base64 iv|tag|ciphertext). The key is made on first use and kept in `data/secrets/kept.json` as `chats.atrest` (DPAPI for this Windows user). Old plaintext files are read as they are and sealed on the next write; start-up seals them all (safe to run again). No key while sealed chats exist: reads and writes are refused with a plain message, never a plaintext fallback. A copy of `data/` only opens for the same Windows user; to take chats elsewhere export plain JSON: `GET /api/dms/contacts/:id/export`, `GET /api/chats/_groups/:id/export` (owner only). AIG-1170 added lead chats `data/<slug>.chat` (the 💚 assistant's `data/_assistant.chat` too), the 🧭 Lead Scrum Master's chat `data/watchman.conf` / `data/watchman.last`, and DM attachments `data/dms/files/<contact>/<id>` (bytes: `aigile-atrest-b1:` + iv|tag|ciphertext, opened when served, content type from the name as before). Still plain: the No AI Scrum Master's `data/smnoai.conf`.
- Sharing (AIG-304/305): `data/shares/<link>.json` per link (git-ignored) holds the link, `outbound` (my share id -> my card id, `stopped` once unticked) and `inbound` (`cards`: the 📥 lane by their share id; `comments`: every comment from them, and mine on lane cards, by share id). A card I ticked 🔗 has `share: { link, id, mine, sent, sentAt, held? }`; a lane card I took has `share: { link, id, theirs }` and `from: 'share:<link>'`. A comment on a shared card has `shared: 'sent' | 'held'`. Friend text is never written into `data/<slug>.json` except a lane card's title when I take it (AIG-306: its description stays in the link file). AIG-306: `outbound[share]` also has `theirStatus` (their status label), `test` (`{ text, at, open, verdict?, note?, answered? }`, a test I handed them) and `files` (my attachment ids already sent); a lane card has `status`, `test` (a test they handed me) and `files` (`[{ id, name, type, size, at }]`), the files themselves in `data/shares/files/<link>/` (owner-only, removed by Unlink and forget). `share.sentStatus` on a card is the last status sent. AIG-324: the link file's `board` (I show them my whole board; such cards have `share.auto`) and `theirBoard` (they show me theirs); `outbound[share].raised` (`{title, description, type, priority}`) is a card I raised on their board, kept only in the link file; a lane card's `myStatus` is the status label I sent on it.
