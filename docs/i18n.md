# Languages (for translators)

AI-gile's page speaks every language that has a file in `public/lang/`. English (`en.json`) is complete and is the fallback: a key missing from your file shows in English, so a file may be partial and can arrive one key at a time. `public/lang/languages.json` lists all 121 languages AI-gile can have (the same set as LocoRadio); the 🌐 picker only offers the ones whose file is in and is valid JSON.

## The rules
1. **Never translate** these; copy them exactly:
   - **AI-gile** and **Claude**, and the model names (Opus, Sonnet, Haiku).
   - Product and platform names: GitHub, Git, VS Code, Discord, Giphy, Windows, Electron, npm, Node.
   - `{placeholders}` such as `{name}`, `{count}`, `{when}`: keep the word inside the braces as it is. You may move a placeholder to wherever your language wants it.
   - Emoji (🗂️ 🧪 ✅ 🌙 ...): keep them, and keep them at the same end of the text where they work as an icon.
   - Anything in `backticks`, file names (`aigile.local.json`), CLI commands (`node aigile.js list`), keyboard keys, card ids (`ALP-12`) and URLs.
2. Keep `**bold**` markers around the same words (translated). Keys ending in `.html` hold markup: translate the text between the tags, never the tags or attributes.
3. `{{dev:commit}}` marks a developer word that gets a tooltip. Translate the word inside the marker the way developers in your language say it (often the English word), and keep the marker: `{{dev:commit}}`.
4. Plurals: a value can be a plural object instead of a string. Give every form your language has (Intl.PluralRules names: `zero`, `one`, `two`, `few`, `many`, `other`); `other` is required. The number comes in as `{count}`.
   ```json
   "quiet.done.told": { "one": "📣 Told {count} team", "other": "📣 Told {count} teams" }
   ```
   Russian, say: `{ "one": "...", "few": "...", "many": "...", "other": "..." }`. A language without plural forms still gives `{ "one", "other" }` with the same text. Where English has a plain string you may give a plain string too.
5. Keep the keys exactly; do not add keys English doesn't have.
6. Casual and short: AI-gile talks to one person at their own computer. Use the informal you where your language has one (du, tu, jij, ti, sinä), plain words, no marketing.
7. Upper-case English strings (column names like `TO DO`) are upper case in your script if it has capitals; scripts without capitals (Hangul, kana, Han, Thai, Devanagari, Arabic...) just translate them.

## Check your file
```
node tools/i18n/check.mjs            # every file in public/lang
node tools/i18n/check.mjs fr de      # just these
node tools/i18n/check.mjs fr --missing   # also list the keys you have not done yet
```
It reports invalid JSON, keys English doesn't have, `{placeholders}` that differ from English, plural objects that are not right, and a file missing from `languages.json`. Missing keys are only counted (English shows instead). It exits 1 when something is wrong. The QA area `i18n` runs it over every shipped file: `node tools/qa/qa.mjs i18n rtl`.

## Add a language
1. Find your language in `public/lang/languages.json`: its `code` is your file name. If it is not there, add an entry: `{ "code": "fr", "label": "FR", "name": "Français", "locale": "fr-FR" }` (`label` is what the 🌐 button shows, `name` is the language's own name, `locale` is what dates use). Add `"dir": "rtl"` for a right-to-left script and `"fun": true` for a fun language.
2. Copy `en.json` to `<code>.json` and translate the values. Partial is fine.
3. Run the checker. Reload the board: the language shows up in **⚙️ Setup → Language** once its file is valid.
4. Word lists that keep a language consistent go in `docs/lang/<code>-glossary.md` (see `nl-glossary.md`).

## How the page picks a language
- A choice made in the picker (**⚙️ Setup**, or the setup wizard) is kept in the browser and always wins.
- With no choice yet, the first of the browser's languages that has a file, with LocoRadio's fallbacks: `nb` and `nn` get Norwegian (`no`), `tl` Filipino (`fil`), `zh-Hant`, `zh-TW`, `zh-HK` and `zh-MO` Traditional Chinese (`zh-tw`), `pt-BR` Brazilian Portuguese (`pt-br`), the old `iw` Hebrew. Otherwise English.
- Fun languages are never picked automatically; the picker lists them last.
- The **quick English switch** (Setup) adds a 🌐 button to the top bar that flips between your language and English in one click.
- Dates and times use `Intl` with the language's `locale`. English follows the browser's English region (en-US, en-AU...), else British.

## Regions: Flemish (`nl-BE`) and Dutch (`nl`)
`nl-BE.json` is Flemish (picker label VL, name Vlaams; LocoRadio calls it `vls`). It carries `"region": "BE", "base": "nl"` and `nl` carries `"notRegion": "BE"`: in Belgium the picker offers Vlaams instead of Nederlands, elsewhere Nederlands and no Vlaams. You are in Belgium when a browser language names it (`nl-BE`, `en-BE`), else by the time zone (Europe/Brussels). A `nl-BE` browser, or plain `nl` in Belgium, starts in Flemish; `nl-NL` starts in Dutch; `fr-BE` gets French once there is a French file. The current language always stays in the picker.

## Right to left
`ar`, `ur`, `fa`, `he`, `ps`, `sd`, `yi` and `ckb` carry `"dir": "rtl"`. The page sets `<html dir="rtl">` and the layout mirrors by itself: the CSS uses logical properties (`margin-inline-start`, `border-inline-start`, `inset-inline-end`, `text-align: start`). Code blocks, commands and the terminal stay left to right. Arabic, Persian, Pashto and Central Kurdish dates use Latin digits (`-u-nu-latn` in their locale). Write numbers and placeholders as usual; the browser places them.

## Notes per language (adapted from LocoRadio)
- **Spanish** (`es`) is Spain Spanish (`móvil`, `vosotros` where it fits, present perfect: "No ha funcionado"); dates `es-ES`.
- **French** (`fr`) is France French, casual with "tu", a non-breaking space before `? ! : ;` and « » quotes; plurals one/other (0 and 1 are singular).
- **Danish, Swedish, Croatian** use the casual you (du / ti); **Finnish** the casual sinä. Finnish and Croatian put a filled-in `{name}` where it can stay in its basic form (no case ending). Croatian plurals are one/few/other.
- **Welsh** (`cy`), **Scottish Gaelic** (`gd`) and **Irish** (`ga`) are three separate languages. Their plurals use every category Intl gives (cy: zero/one/two/few/many/other; gd: one/two/few/other; ga: one/two/few/many/other). A filled-in name never sits where a mutation would change it.
- **Chinese**: `zh` is Simplified (Mainland), `zh-tw` Traditional with Taiwan vocabulary.
- **Portuguese**: `pt` is Portugal, `pt-br` Brazil. **Norwegian** `no` is Bokmål. **Serbian** `sr` is Cyrillic; **Uzbek**, **Azerbaijani** and **Bosnian** are Latin; **Burmese** is Unicode, not Zawgyi.
- **Arabic** uses all six plural categories (zero, one, two, few, many, other); **Hebrew** one, two, other.
- **Small and regional languages** (Breton to Central Kurdish in `languages.json`) are mostly written and reviewed by models: native review matters most there. Where Intl has no data (Cornish, Manx, Haitian Creole, Guaraní) the `locale` is a neighbouring one.
- **Fun languages** (`"fun": true`): Pirate, Esperanto, Interlingua, Klingon, Sindarin, Quenya, Dothraki, Na'vi, Toki Pona, Lojban, Yoda, Shakespeare, Old English, Emoji, leet and Morse. Sindarin, Quenya, Dothraki, Na'vi and Klingon are English with real attested words; Toki Pona, Lojban and Old English are real translations; Yoda, Shakespeare and Emoji are English rewrites. leet and Morse are best made by a script from `en.json` (letters swapped, placeholders, markers and emoji kept). The rules above still hold: AI-gile, Claude and `{placeholders}` stay as they are.
- **Dutch and Flemish** word choices: `docs/lang/nl-glossary.md` and `docs/lang/nl-BE-glossary.md`.

## For developers
- In script: `t('key', { name })`; plurals `t('key', { count: n })`. Dates: `d.toLocaleDateString(i18n.locale, opts)`. In `index.html`: `data-i18n`, `data-i18n-title`, `data-i18n-label`. More in `docs/codemap/languages.md`.
- A new plural key: give English `{ "one", "other" }` with `{count}`. Only where a number really sits next to a noun.
