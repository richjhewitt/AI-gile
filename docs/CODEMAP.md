# Code map

Index of where things live. Detail per area is in `docs/codemap/*.md`; read only the area you touch. In each file, search for the `/* ---------- name ---------- */` markers rather than relying on line numbers.

## Run and test
- Server: `node server.js` (or `start-aigile.bat`) -> http://localhost:4321. `AIGILE_PORT` and `AIGILE_DATA` change the port and data folder; `AIGILE_DEV=1` adds the "new version, refresh" prompt.
- CLI: `node aigile.js help` (`AIGILE_URL` points it at another server; `AIGILE_AS` sets the author).
- QA: `node tools/qa/qa.mjs [area ...]` (no args = all; `--list` shows them; `QA_PORT`, default 4390). Own server on a temp folder, live board untouched. Runner, helpers, area files, AI tester: [qa.md](codemap/qa.md).

- `lib/phone.js` + `lib/routes/phone.js` + `public/js/phone.js` (AIG-868): 📱 your phone over your own Tailscale network (`tailscale serve --bg 4321` on the PC). Setup's Phone box: host (prefilled from read-only `tailscale status --json`), Pair a phone -> `https://<host>/#/pair/<code>` + QR (inline encoder, byte mode, level M, v1-6; code 10 min, once, in memory). `server.js` `guardPhone`: a saved host (`phone.hosts` in aigile.local.json) needs the `aigile_phone` cookie (HttpOnly, Secure, SameSite=Strict; only its sha256 is saved in `phone.devices`) or the `POST /api/phone/pair` call, and Origin `https://<host>` (required for non-GET); `req.aigilePhone` marks it. A phone is refused `/api/phone/*`, terminal, secrets, editor, `POST /api/setup` and any body with `runCmd`/`runIn` (`phone.denied`/`deniedBody`; terminal.js and secrets.js also refuse it, as tailscale serve comes from 127.0.0.1). Routes: `GET /api/phone`, `GET /api/phone/tailscale`, `POST /api/phone/start {host, name}`, `DELETE /api/phone/devices/:id`, `POST /api/phone/pair {code}` (sets the cookie via `__cookie`). Page: `Phone.ready()` runs in app.js start-up (pairs, or shows "not paired"; `Phone.blocked` holds core.js refresh); texts `phone.*`; QA `phonepair`. AIG-907 (Android app): **Pair the app** (`POST /api/phone/app {host}`) makes a device key at once ("Android app", hash only) shown once as the QR text `aigile://pair?url=https://<host>&key=<key>`; the app sends `Authorization: Bearer <key>` (same lookup, host binding and deny list; any Authorization header means only the Bearer is checked), and a valid Bearer may POST without Origin (a cross-site page cannot send that header: no CORS preflight is ever answered). AII-18 sealed link (spec + vectors in `docs/SEALED.md`): `lib/phone-seal.js` (HKDF seal key `S` per device as `seal`, AES-256-GCM, ±120 s, nonce memory 10 min) and `runSealed` in server.js (`POST /api/phone/sealed` + `X-Aigile-Device`, inner request through the same routes and deny list); QR now `aigile://pair?url=&id=&key=`; `/api/meta` has `sealed: 1`; QA `phonesealed`
